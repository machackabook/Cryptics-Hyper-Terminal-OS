# GAIA device and AI collaborator orchestration contract

## Closed-loop objective
GitHub failures → ADAM diagnosis → agent ownership → Grok/AI Factory patch proposal → CI gates → signed OmniApp package → opted-in device staging → health evidence → promotion or rollback → Memory Fabric.

## Current delivered component
Read-only GitHub Actions failure intake, revision-bound remedy job identities and downloadable evidence artifacts. It does not yet claim AI patch execution or device deployment.

## Required adapters
- **AI contributors:** authenticated GitHub PR submissions from Grok and other AI entities; never assume an entity is connected until its actual identity and permissions are verified.
- **GAIASWINDOW:** Windows service reporting signed health, versions and deployment outcomes.
- **Samsung:** Android-compatible managed app updater and explicit app permissions; no assumption Termux is installed.
- **Chromebook:** supported Linux container / browser PWA deployment, scoped by device capability.
- **Web TV:** platform-specific signed app package or PWA, respecting webOS/browser restrictions.
- **Google Drive:** authenticated, versioned, provenance-preserving source and evidence synchronization.
- **Network:** least-privilege node authentication, transport encryption, segmentation, and device-scoped allowlists.

## Promotion policy
Autonomous safe actions: inspect, classify, generate test-only patch branches, run verification, create draft PRs, package in sandbox, and restore last-known-good artifacts.
Controlled actions: security policy changes, privileged installations, router changes, destructive operations, or permission expansion require explicit authorization.
Every failed attempt remains a remedy job with evidence; no fake green check or silent deletion.

## Durable next gate
Replace per-run artifact-only queues with an authenticated persistent work queue, job leases, deduplication, backoff, bounded retries, observability, and replay-safe transport.
