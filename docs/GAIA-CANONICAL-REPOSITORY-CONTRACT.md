# GAIA canonical repository and promotion contract

## Canonical roles (all use main)
1. **machackabook/main** — public beta, experimental development, real GitHub Pages validation, legal and ethical constraints.
2. **Azazeleous/main** — promoted Cryptic News service distribution, consuming the same verified components and artifact contracts.
3. **NexusCryptic / CrypticNexus organization main** — durable release archive, versioned evidence and recovery copies. Organization spelling and repository paths must be resolved before automation.

These are three **repository roles**, not a policy to create three development branches in each repository. There is no feature-branch backlog in the normal beta path.

## Invariants
- New capabilities land on machackabook/main as cohesive, integrated commits, not scattered branch-specific features.
- Every commit produces discoverable artifacts: revision, changed paths, provenance, test receipts, ADAM remedy jobs, and promotion eligibility.
- ADAM automatically queues missing evidence and corrective work; failures do not erase last-known-good builds.
- Shared interface contracts cover Golden Army, AI Factory, OmniApp Store, GAIA Nexus, Samsung, Chromebook, GAIASWINDOW, and webOS.
- Promotion to Azazeleous and archival mirror requires genuine verification and authenticated target repository permissions.
- Do not bypass required GitHub protections, forge passing results, expose secrets, or automatically perform privileged device changes.

## Known current gaps
- The exact Azazeleous service repository and organization archive repository have not been verified.
- Real cross-repository mirroring, signed release promotion, and device distribution are not yet implemented.
- A main-branch commit alone is not evidence of successful deployment.
- Existing GitHub Actions failures need root-cause correction and automatic remedy worker execution.

## Current immediate workflow
machackabook/main push → GitHub Actions → source discovery → canonical naming check → verification receipts → remedy intake → corrected main commit → verified artifact → authorized promotion → archive.
